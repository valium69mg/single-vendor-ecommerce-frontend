### ~~Duplicated logic — `formatDate` copy-pasted~~ ✅ Fixed in `2bf0b0f`

### Duplicated logic — `InfiniteScrollSelect` / `InfiniteScrollMultiSelect` are near-clones
- `src/components/common/InfiniteScrollSelect.tsx:27` and `src/components/common/InfiniteScrollMultiSelect.tsx:27` — Both have the same 4 `useEffect`s (portal position, outside-click, focus, IntersectionObserver sentinel), the same refs, the same infinite query setup, and the same portal rendering. Extract a `useInfiniteDropdown` hook that owns the open/close mechanics, and let the two components focus on selection mode only.

### Oversized component — `CreateProductForm`
- `src/components/products/CreateProductForm.tsx:514` — Main export is 983 lines total; the `CreateProductForm` component starts at line 514 and handles 3-step form state, 5 useState calls, 1 useEffect, multiple mutations, and all render. The file also defines 4 private sub-components. The main form logic (steps, mutations, handlers) should be extracted into a `useCreateProductForm` hook, trimming the component to a pure rendering shell.

### Effect misuse — derived `attrTagsMap` sync via effect
- `src/components/products/CreateProductForm.tsx:563` — `useEffect` syncs `attrTagsMap` when `fields` changes (sets new field IDs to empty arrays). This is state-derived-from-state via an effect, causing an extra render cycle. The correct approach: initialise the map entry in `handleAddVariant` when appending the field, and clean it up in `handleRemoveVariant`. The effect at line 563 can be deleted.

### Effect misuse — `SearchBar` syncs debounced value through effect
- `src/components/common/SearchBar.tsx:16` — `useEffect(() => { setQuery(debouncedValue) }, [debouncedValue, setQuery])`. The debounced value is derived state; the effect fires to propagate it upward. This is the pattern of "sync external state via effect." The cleaner approach is to expose the debounced value through the hook and let the parent decide, or use a controlled pattern so `setQuery` is called in the change handler with debouncing done in the parent. As-is it also requires `setQuery` to be stable (must be memoised by the caller), which is not enforced.

### Re-render waste — inline `setPage` arrow functions passed as props on every render
- `src/pages/AdminCategoryDetailPage.tsx:258` and `:274` — `setPage={() => {}}` passed inline to `DataTable`; creates a new function reference on each render. Trivially fixed with a stable no-op const: `const noop = useCallback(() => {}, [])`.

### Re-render waste — `tableLabels` object created on every render in `AdminCategoryDetailPage`
- `src/pages/AdminCategoryDetailPage.tsx:156` — `const tableLabels = { ... }` is a plain object literal created fresh every render. Since it is passed as a prop to two `DataTable`s, both receive a new reference on every render. Wrap in `useMemo` or hoist outside the component (the values are already translated strings from `t()`, so `useMemo` with `[t]` is sufficient).

### Missing async state — no error handling after `imageMutation` fails silently
- `src/components/products/CreateProductForm.tsx:650` — `imageMutation.mutateAsync` is called inside a try/catch that only shows a toast for image errors. If `imageMutation` itself throws (network error), the outer catch at line 668 will show the generic product error. Image upload failure is distinct from product creation failure — the product was already created. Surface a clearer message.

### Context — `UserContext` value object recreated on every `user` state change
- `src/providers/UserProvider.tsx:18` — The `value` object `{ user, setUser, logout }` is an inline object literal. Every time `user` changes, all `UserContext` consumers re-render regardless of whether they use `setUser` or `logout`. If consumers grow, split into a stable-value context (setUser, logout) and a volatile context (user) and provide them separately.

### Magic values — hardcoded status strings in filter options
- `src/pages/AdminProductsPage.tsx:289-291` — `"ACTIVE"`, `"INACTIVE"`, `"DRAFT"` hardcoded in JSX option values with Spanish display labels inline (`Activo`, `Inactivo`, `Borrador`). These status strings should come from a constants file (`src/constants/productStatus.ts`) to prevent typo drift and enable i18n consistency.

### Magic values — low-stock threshold duplicated
- `src/pages/AdminCategoryDetailPage.tsx:22` — `LOW_STOCK_THRESHOLD = 10` defined; but `src/hooks/useCategoryColumns.tsx:114` hardcodes `<= 10` for stock colouring. The threshold is duplicated in two places — import the constant or centralise it.

### Accessibility — `ImageWithFallback` has optional `alt` defaulting to empty string
- `src/components/common/ImageWithFallback.tsx:11` — `alt=""` is only correct for decorative images. In `useCategoryColumns.tsx:44` and `AdminCategoryDetailPage.tsx:208`, the component is rendered with a real alt (`row.original.name`, `data.name`), so that call site is fine. But the default `alt=""` means any future careless usage silently omits the alt. Make `alt` required unless the caller explicitly opts into decorative via `alt=""`. At minimum, leave a comment documenting the intent.

## Suggestion

### Duplicate TypeScript interfaces — `CreateCategoryFormContentProps` / `EditCategoryFormContentProps`
- `src/components/categories/CreateCategoryForm.tsx:21` and `src/components/categories/EditCategoryForm.tsx:25` — Both `*FormContent` sub-components accept `(register, errors)`. The interfaces are nearly identical, differing only in the `data: Category | undefined` field in the edit version. Could share a base interface and extend with the optional `data` field.

### Duplicate TypeScript interfaces — `FormContentProps` / `FormHeaderProps` / `FormFooterContentProps` in `Form.tsx`
- `src/components/common/Form.tsx:19-31` — `FormContentProps`, `FormHeaderProps`, and `FormFooterContentProps` are all thin wrappers used by private sub-components that are not exported. Defining three named interfaces for internal-only props is over-engineering; inline the types directly in the sub-component signatures.

### Hook extraction — `useCategoryColumns` and `useProductColumns` return columns but aren't truly hooks
- `src/hooks/useCategoryColumns.tsx:23` and `src/hooks/useProductColumns.tsx:18` — Both are named `use*` but the only hook they call is `useTranslation`. This is fine, but the `formatDate` utility and column cell JSX could move to a non-hook module (e.g. `src/components/admin/columns/`). The hook wrapper exists only because of `useTranslation`. If the column definitions were moved to component level these could be plain functions.

### File organisation — multiple private sub-components in `Form.tsx`
- `src/components/common/Form.tsx:32-57` — `FormHeader`, `FormContent`, and `FormFooter` are defined and used only within this file, but they are named in PascalCase as if they were exported. Since they are genuinely private, they could be inlined into the `Form` function body or named with a `_` prefix to signal internal scope. Convention should be consistent with the rest of the codebase.

### Dead code — `data &&` guard after already checking `!data` earlier
- `src/pages/AdminCategoryDetailPage.tsx:280` — `{data && (` wraps the actions section, but `data` is already guaranteed non-null by the early return at line 167 (`if (!data) return ...`). The `&&` check is unreachable falsy and adds visual noise — remove it.

### Magic values — hardcoded pagination sizes (10, 25, 50) repeated
- `src/pages/AdminProductsPage.tsx:276-279` and `src/pages/AdminCategoriesPage.tsx:15` — `SIZE = 10` and the per-page options `10/25/50` are inline. Extract to a shared `PAGINATION` constants object.

### Repeated Tailwind class strings — textarea input class repeated verbatim
- `src/components/products/CreateProductForm.tsx:756` and `:769` — `"w-full px-3 py-2 text-sm font-store-body border border-stone-300 rounded-none bg-white focus:outline-none focus:border-stone-600 transition-colors placeholder:text-stone-400 resize-none"` is identical on both textarea elements (shortDescription and longDescription). Extract into a `textareaClassName` constant at the top of the component, or better, into a shared `<FormTextarea>` component consistent with the existing `FormField`.

### Accessibility — icon-only remove buttons lack accessible name
- `src/components/products/CreateProductForm.tsx:347` — `<button>×</button>` removes an attribute value tag; the visual "×" character has no `aria-label`. Screen reader users hear "button" only.
- `src/components/common/InfiniteScrollMultiSelect.tsx:232` — Same pattern on the `<X>` remove chip button. Add `aria-label={t("remove") + " " + selectedLabels[idx]}` (or equivalent).

### Hygiene — `EditImageForm.tsx` has English copy in JSX
- `src/components/common/EditImageForm.tsx:42` — `<span>Click to upload image</span>` is hardcoded English in the JSX of a Spanish-first project. Should use `t("clickToUploadImage")` or equivalent translation key.

### Hygiene — `Form.tsx` renders `<></>` for missing description
- `src/components/common/Form.tsx:43` — `else { return <></> }` instead of `null`. Both are equivalent but `null` is the idiomatic React "render nothing" return. Minor readability issue.
